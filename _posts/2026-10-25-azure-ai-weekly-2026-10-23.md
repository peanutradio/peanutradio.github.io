## 네트워크

### Traffic Manager 연결 레코드 — Azure DNS (GA)

Azure DNS 레코드 세트를 Traffic Manager 프로필에 직접 연결할 수 있다. 지금까지는 trafficmanager.net을 가리키는 CNAME을 만들어야 했는데, 그 단계가 없어진다. 공지는 CNAME 조회 한 번이 빠져 지연이 줄고, 서명되지 않은 trafficmanager.net이 해석 경로에서 빠져 로드 밸런싱 레코드에도 DNSSEC을 쓸 수 있게 된다고 설명한다.

DNS 기반 분산을 쓰면서 DNSSEC 도입이 막혀 있던 팀이 대상이다.

도입 전에는 기존 CNAME 방식에서 연결 레코드로 옮기는 절차와 지원 조건을 Learn 문서(dns-traffic-manager-linked-records)에서 확인해야 한다.

### Application Gateway Keyless TLS — Key Vault Managed HSM (GA)

TLS 인증서의 개인 키를 Managed HSM에 두고, 핸드셰이크 서명을 HSM 안에서 처리한다. 개인 키는 게이트웨이로 내보내지 않는다. 공지에 따르면 접근은 관리 ID와 RBAC로 제어하고, 서명 작업은 Managed HSM 진단 로그로 볼 수 있으며, 키는 FIPS 140-3 Level 3 검증 HSM에 생성·보관된다.

키 보관 위치 증빙이 필요한 금융·공공 성격의 워크로드가 신경 쓸 항목이다.

도입 전에는 Managed HSM 자체가 별도 리소스라는 점과 구성 절차(aka.ms/appgw/keylesstls/configure 튜토리얼)를 확인한다.

### Front Door Premium WAF 서비스 태그 조건 (GA)

WAF 사용자 지정 규칙에서 요청의 원본 IP를 서비스 태그와 비교할 수 있다. 서비스 태그는 Microsoft가 주소 변경에 맞춰 자동 갱신하므로 IP 목록을 직접 관리하지 않아도 된다. 공지가 든 활용은 필요한 Azure 서비스 허용, 불필요한 서비스 차단, 관리자 경로 제한, 속도 제한이다.

Front Door 뒤에서 상태 검사나 모니터링 트래픽을 IP로 허용하던 운영자에게 해당된다.

Premium 계층 전용 조건이므로 현재 SKU를 먼저 확인하고, 차단 규칙은 적용 전에 허용해야 할 서비스 태그가 빠지지 않았는지 점검한다.

### VNet 피어링 경로 끄기 (프리뷰)

경로 테이블에 연결된 서브넷에서 시스템이 만든 피어링 경로를 억제하되 피어링 연결은 유지한다. 허브 앤 스포크 구조에서는 요약된 UDR 하나로 트래픽을 Azure Firewall 같은 NVA로 보내, 스포크마다 덮어쓰기 경로를 두지 않아도 된다. 경로 테이블 설정이나 Azure Virtual Network Manager 라우팅 규칙 컬렉션으로 관리한다.

대규모 허브 앤 스포크에서 UDR이 늘어나 고민인 네트워크 담당자가 볼 만하다.

이 기능은 대체 UDR과 검사 경로를 자동으로 만들어 주지 않는다. 직접 구성해야 하고 프리뷰이므로 운영 환경 적용은 신중해야 한다.

## 데이터·스토리지

### Azure Backup VM 항목 수준 복구 — Premium SSD v2·Ultra (GA)

Premium SSD v2와 Ultra 디스크를 쓰는 VM에서도 파일·폴더 단위 복구를 지원한다. 512바이트와 4KB 논리 섹터 모두 해당한다. 포털, CLI, PowerShell로 복구용 실행 파일이나 스크립트를 만들고, 호환되는 머신에서 실행해 복구 지점을 찾아보며 필요한 파일만 복사한다. 기존 ILR과 같은 방식이다.

고성능 디스크를 쓰는 VM에서 전체 복원 없이 파일 하나를 되살려야 하는 운영자에게 필요하다.

복구를 실행할 머신의 호환 조건은 Azure Backup what's new 문서에서 확인한다.

### ABFS Vectored Read — Azure Data Lake Storage (GA)

인접한 파일 범위를 묶어 더 적은 스토리지 요청으로 읽고, 읽기를 비동기로 실행한다. 선택적 Parquet 쿼리처럼 일부만 읽는 작업에서 네트워크 왕복을 줄이는 것이 목적이다. 호환되는 Spark 워크로드는 설정만으로 켤 수 있어 쿼리 재작성이나 데이터 이전이 필요 없다고 한다.

ADLS 위에서 Spark로 분석하는 데이터 엔지니어가 대상이다.

호환 엔진과 설정 키는 Tech Community 글에서 확인하고, 효과는 워크로드에 따라 다르므로 자기 쿼리로 먼저 비교해야 한다. 공지는 성능 수치를 제시하지 않았다.

### Cosmos DB 안전한 키 회전 (GA)

계정 키별로 마지막 사용 시각 메타데이터를 볼 수 있다. 아직 쓰이는 키를 확인하고 나서 회전하거나 폐기할 수 있어, 쓰고 있는 키를 꺼서 생기는 서비스 중단 위험이 줄어든다.

키 기반 인증을 쓰는 애플리케이션이 많은 팀이 키를 정리할 때 도움이 된다.

사용 시각을 확인한 뒤에도 클라이언트 쪽 키 교체 순서는 직접 계획해야 한다. 절차는 Cosmos DB 키 회전 문서를 따른다.

## 보안·ID

### Entra Choose Your Own Telephony (GA 예정, 2026-10-30)

2026-10-30부터 Entra ID에서 지원되는 서드파티 통신사를 SMS·음성 인증에 쓸 수 있다. Microsoft Security Store에서 제공자를 고르고 계약과 비용은 제공자와 직접 관리한다. 공지는 패스키 같은 피싱 방지 방식을 권장하며, 업무·규제·기술상 전화 인증이 꼭 필요한 사용자군에만 쓰라고 한다.

SMS·음성 MFA에 의존하는 테넌트 관리자가 해당한다. Microsoft 제공 SMS·음성 인증은 2027-02-01부터 은퇴가 시작된다.

공지가 권하는 준비 항목은 대상 사용자 식별, 피싱 방지 대안 검토, 제공자별 지역·채널·가격 비교, 조달·개인정보 요건 검토, Azure 구독 구매 자격과 비용 추정이다.

## 운영·모니터링

### Azure Monitor 고급 플랫폼 지표 (GA)

더 세밀한 신호로 리소스의 변화와 추세를 빨리 찾게 해 주는 기능이다. 이제 Azure 포털에서 직접 켤 수 있고, 아직 켜지 않은 구독에는 안내 배너가 뜬다. Fairfax와 Mooncake에서도 쓸 수 있다. 프리뷰는 2026-07에 시작됐다.

여러 구독을 운영하는 관리자는 구독별로 활성화 여부를 확인할 필요가 있다.

공지에 비용 정보가 없으므로 켜기 전에 요금 문서를 확인한다.

### Azure Monitor 작업 영역 지표 사용량 인사이트 (GA)

작업 영역의 사용률, 쓰지 않는 지표, 사용 추세, 수집량 변화의 원인을 볼 수 있다. 비용 최적화와 용량 계획이 목적이다.

Prometheus 계열 지표 수집 비용을 관리하는 플랫폼 팀에 쓸모가 있다.

화면 위치와 필요한 권한은 Learn 문서(metrics-usage-insights)에서 확인한다.

## 은퇴·마감 알림

- 2026-10-30: Entra CYOT 제공 시작(공지의 GA 목표일).
- 2027-02-01: Microsoft 제공 SMS·음성 인증 은퇴 시작. 은퇴 지침은 Learn의 concept-sms-voice-retirement 문서에 있다.

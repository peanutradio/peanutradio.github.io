## 네트워크

### Route Server 라우트 맵 (GA)

Azure Route Server에서 광고하거나 수신하는 경로를 인바운드·아웃바운드 양쪽에서 더 세밀하게 제어하는 기능이 Azure 퍼블릭 클라우드에서 GA가 됐다.

NVA와 온프레미스를 BGP로 엮어 쓰는 하이브리드 네트워크 담당자가 볼 항목이다. 경로를 걸러내거나 바꾸려고 NVA 쪽에 정책을 따로 두던 구성이라면 정리할 여지가 있다.

도입 전에는 지금 정책이 어디에 있는지(NVA인지 온프레미스 라우터인지)부터 적어 두고, 라우트 맵을 켰을 때 어느 경로가 바뀌는지 비프로덕션에서 확인하는 것이 좋겠다. 소버린·정부 클라우드 지원 여부는 내가 읽은 본문에서 확인하지 못했다.

### Azure Firewall IPv6 애플리케이션 규칙 (프리뷰)

IPv6 HTTP/HTTPS 트래픽에 대해서도 L7 필터링(애플리케이션 규칙)을 쓸 수 있게 됐고, 듀얼 스택 배포까지 범위가 넓어진다.

IPv6를 도입 중이거나 듀얼 스택으로 가야 하는 조직이 해당된다. 지금까지 IPv6 쪽은 FQDN 기반 제어가 막혀 있었다면 검토 대상이다.

프리뷰이므로 SLA와 지원 범위를 확인하고, 기존 IPv4 규칙과의 우선순위 동작을 테스트 환경에서 먼저 보는 편이 안전하다.

### Application Gateway for Containers — 프라이빗 인그레스·JWT 검증·MCP 게이트웨이 (프리뷰)

AGC에 세 가지가 동시에 프리뷰로 들어왔다. 프라이빗 인그레스는 승인된 Private Link 프라이빗 엔드포인트로만 접근 가능한 프런트엔드를 만들어 내부 앱과 클러스터 사이 트래픽을 사설로 유지한다. JWT 검증은 `AuthPolicy` 커스텀 리소스로 서명·issuer·수명·audience를 게이트웨이에서 검사한다. MCP 게이트웨이는 `MCPRoute` 커스텀 리소스로 MCP 서버를 안정적인 호스트명·경로로 게시하고 TLS, JWT 검증, WAF를 한곳에 모은다.

AKS에서 내부 API나 MCP 서버를 운영하는 팀이 대상이다. 에이전트가 호출하는 MCP 서버마다 인증을 따로 구현하고 있다면, 게이트웨이에서 중앙화하는 방향을 비교해 볼 만하다.

세 기능 모두 프리뷰다. 이미 쓰는 인그레스 구성과의 전환 비용, 신뢰할 서명 키 소스 설정 방식을 공식 문서에서 확인한 뒤 PoC로 시작하자.

## 보안·ID

### Front Door TLS 키 교환 정책, 포스트퀀텀 지원 (GA)

Azure Front Door에서 TLS 키 교환 정책을 구성할 수 있게 됐고, 하이브리드 포스트퀀텀 키 교환이 포함된 사전 정의 정책 중에서 고르는 방식이다.

장기간 보관되는 민감 데이터를 다루거나 규제·보안 정책상 양자 내성 암호 로드맵을 요구받는 조직이 먼저 볼 항목이다.

정책을 바꾸면 클라이언트 호환성에 영향이 있을 수 있다. 사전 정의 정책별 지원 범위는 본문이 잘려 확인하지 못했으니, 공식 항목에서 정책 목록을 확인하고 단계적으로 적용하자.

### WAF Insights for Application Gateway (GA)

WAF 정책 안에 내장된 경험으로, WAF 로그와 메트릭을 대화형 대시보드로 모아 차단 내역을 조사할 수 있다.

WAF를 켜 놓고 로그 분석을 쿼리로만 해 오던 운영자가 대상이다. 오탐 튜닝 시간을 줄일 수 있는지 볼 만하다.

대시보드가 의존하는 진단 설정(Log Analytics 연동 등)이 필요한지는 본문에서 확인하지 못했다. 켜기 전에 확인하자.

## 데이터·스토리지

### PostgreSQL Flexible Server — VNet 통합에서 프라이빗 엔드포인트 가능 구성으로 전환 (GA)

기존에 VNet 통합(위임 서브넷)으로 만든 서버를 프라이빗 엔드포인트가 가능한 네트워크 구성으로 바꿀 수 있게 됐다. 같은 날 Flexible Server의 안정 REST API 버전 `2026-10-01`도 GA가 됐고, 유지보수 관리·불변 백업·멀티테넌트 암호화 같은 확장이 포함된다고 소개돼 있다.

VNet 통합으로 시작했다가 프라이빗 엔드포인트 구조로 가고 싶었던 팀, 그리고 IaC·SDK로 API 버전을 고정해 두는 팀이 볼 항목이다.

전환 중 연결 중단이 있는지, 전환 후 DNS·클라이언트 연결 문자열을 바꿔야 하는지는 확인하지 못했다. 운영 서버에 적용하기 전 공식 절차를 확인하자.

### SQL Database·Managed Instance PITR 백업 불변성 연장 (프리뷰)

기본 7일인 불변 백업을 넘어, 설정한 PITR 보존 기간까지 불변 보존을 잠글 수 있다. 35일 보존을 쓰는 금융 고객 같은 사례가 예로 언급된다.

랜섬웨어·내부자 위협 대응이나 감사 요건으로 백업 변경 불가를 요구받는 조직이 대상이다.

잠그면 되돌릴 수 없는 성격일 가능성이 있으니(본문에서 확인하지 못한 부분이다), 보존 기간과 비용을 먼저 확정하고 비프로덕션 DB에서 동작을 확인하자.

### Service Bus Premium 파티션 네임스페이스 지역 복제 (GA)

파티션 네임스페이스에서 메시지와 메타데이터를 보조 리전에 복제하는 기능이 GA가 됐다. 파티셔닝의 처리량과 복제를 함께 쓸 수 있다.

고처리량 메시징에 DR이 필요한 팀이 대상이다. 이전에는 둘 중 하나를 고르는 구조였다면 설계를 다시 볼 이유가 된다.

복제 지연, 장애 조치 방식, 비용은 확인하지 못했다. 목표 복구 시간 요건과 맞는지 공식 문서에서 따져 보자.

## 운영·모니터링

### Azure Site Recovery for Azure Local (GA)

Azure Local의 Windows·Linux VM을 보호하고 복제하는 기능이 GA가 됐고, 설정과 보안을 단순화한다고 소개된다. 같은 주에 VMSS Flex 대상 ASR 지원 개선도 GA로 나왔다.

Azure Local로 온프레미스 워크로드를 돌리는 조직과 VMSS Flex 기반 서비스의 DR 담당자가 대상이다.

지원 OS·구성과 복제 대상 리전, 요금은 본문에서 확인하지 못했다. 현재 DR 방식과 비교해 전환 여부를 정하자.

### 멀티 디스크 crash-consistent VM 복원 지점 — Premium SSD v2·Ultra (프리뷰)

SCSI 디스크 컨트롤러 VM에서 Premium SSD v2와 Ultra 데이터 디스크를 대상으로 멀티 디스크 crash-consistent 복원 지점을 에이전트 없이 만들 수 있다.

DB처럼 여러 디스크에 걸친 데이터 일관성이 필요한 VM 운영자가 대상이다.

NVMe 컨트롤러 VM은 조건에서 빠져 있다. 우리 VM이 SCSI인지 먼저 확인하고, crash-consistent이므로 애플리케이션 일관성이 필요한 경우 별도 방안을 고려하자.

## 은퇴·마감 알림

- **Azure Fluid Relay**: 2027년 6월 2일에 은퇴한다. 그 이후 서비스를 쓸 수 없고, 계속 의존하는 워크로드는 장애가 날 수 있다. Fluid Framework 자체는 오픈소스로 계속 제공된다는 문장이 있다. 대체 서비스·마이그레이션 안내는 내가 읽은 본문에서 확인하지 못했다.
- **Microsoft Defender for IoT의 OT 보안**: deprecate 공지가 나왔고, 3년 전환 기간 뒤 2029년 10월에 완전 지원이 종료된다. 대체 제품과 권장 조치는 본문이 잘려 확인하지 못했다.

Fluid Relay는 만료까지 약 7개월이다. 사용 중인지 구독을 점검하는 것부터 시작하자.

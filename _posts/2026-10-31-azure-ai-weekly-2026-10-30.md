## 네트워크

### Front Door 프로필·라우트 단위 WAF 정책 (GA)

Azure Front Door Premium의 WAF 정책이 도메인 단위에 묶이지 않고, 프로필 전체나 라우트 단위로도 적용된다. 공식 안내는 프로필 전반에 기본 보호를 깔고, 필요한 곳에만 더 세밀한 정책을 얹는 구성을 말한다.

도메인이 많은 Front Door를 운영하면서 도메인마다 WAF 정책을 따로 관리해 온 팀이 대상이다.

도입 전에는 기존 도메인 단위 정책과 새 프로필·라우트 정책이 겹칠 때의 우선순위 규칙을 공식 문서에서 확인해야 한다. 이 부분은 이번 게시물 요약에서 확인하지 못했다.

### Front Door Premium HTTP DDoS 룰셋 (GA)

Front Door Premium WAF에 HTTP 계층 DDoS 방어용 룰셋이 GA로 추가됐다. 공식 안내는 IP 필터나 고정 속도 제한 같은 정적 통제만으로는 한계가 있다는 점을 배경으로 든다.

Premium SKU로 웹 앱을 공개하고 있고 HTTP 플러드로 인한 가용성이 걱정인 팀이 대상이다.

도입 전에는 기본 동작 모드(탐지만 할지 차단할지)와 오탐 시 예외 처리 방법을 문서로 확인해야 한다. 요약에서 확인되지 않은 항목이라 단정하지 않는다.

### VNet 플로우 로그 필터링 (GA)

Network Watcher VNet 플로우 로그에서 IP 주소, 포트, 프로토콜, 암호화 상태, 플로우 상태, 트래픽 방향 같은 조건으로 기록할 트래픽을 고를 수 있다.

Learn 개요 문서를 보면 VNet 플로우 로그는 게이트웨이 트래픽까지 기본으로 잡기 때문에 로그량이 늘 수 있고, 과금은 수집 GB 기준(구독당 월 5GB 무료)이다. 로그량과 비용을 줄이려는 팀에 필터가 의미 있다.

도입 전에는 필터로 뺀 트래픽이 보안 조사 때 필요하지 않은지 먼저 따져야 한다. 같은 문서에 NSG 플로우 로그와 VNet 플로우 로그를 같은 워크로드에 함께 켜면 중복 기록과 추가 비용이 생길 수 있다는 권고도 있다.

## 데이터·스토리지

### 스토리지 계정 쿼터 상향 (GA)

표준 엔드포인트 스토리지 계정을 리전·구독당 기본 250개에서 최대 1,000개까지 만들 수 있다. Learn 문서에는 "기본 250, 요청 시 1,000"으로 적혀 있다.

한 구독에 스토리지 계정을 많이 쪼개 쓰는 멀티 테넌트·SaaS형 구성이 대상이다.

도입 전에는 쿼터 증액이 요청 절차(Azure Quotas)를 거치는 방식이라는 점을 확인해야 한다. 같은 문서에서 Azure DNS zone 엔드포인트(프리뷰)는 2027년 3월 은퇴 예정이라고 하니, 개수를 늘리려고 그쪽을 쓰고 있다면 표준 엔드포인트로 옮겨야 한다.

### Azure Backup 교차 테넌트 복원 (프리뷰)

Azure VM 백업을 별도 Azure 테넌트로 복원하는 Cross-Tenant Restore가 프리뷰로 나왔다. 기존 백업 사본을 그대로 쓰면서 독립된 복구 경로를 만든다는 것이 공식 설명이다.

랜섬웨어·테넌트 침해 대비로 복구 경로를 분리하려는 보안·백업 담당자가 대상이다.

프리뷰이므로 운영 복구 절차의 유일한 수단으로 두지 않아야 한다. 지원 범위(VM 종류, 리전)는 공식 문서에서 확인해야 한다.

### Azure SQL 데이터베이스 수준 관리 ID (프리뷰)

Azure SQL Database에서 데이터베이스마다 사용자 할당 관리 ID를 지정해, 외부 테이블과 OPENROWSET으로 Blob Storage·ADLS Gen2 파일을 조회할 수 있다. 제목에는 FIC(페더레이션 ID 자격 증명)도 지원한다고 되어 있다.

서버 단일 ID를 여러 DB가 공유하던 구조에서 DB별로 권한을 나누고 싶은 팀이 대상이다.

프리뷰이므로 스토리지 쪽 역할 할당(RBAC) 방식과 T-SQL 구문을 공식 문서로 확인해야 한다.

## AI·에이전트

### Azure MCP Server 3.0 (GA)

Azure MCP Server 3.0이 GA다. AI 에이전트와 개발 도구가 오픈 MCP로 Azure에 접근하는 서버이고, 이번 릴리스에서 인프라 as 코드(Azure Terraform 관련) 등 기능이 추가·확장됐다. 전체 목록은 게시물이 길어 일부만 확인했다.

에이전트에 Azure 리소스 조작 권한을 연결하려는 개발자가 대상이다.

도입 전에는 에이전트가 쓰는 ID의 권한을 최소로 두고, 쓰기 작업이 가능한 도구를 어디까지 열지 정해야 한다. 2.x에서 올릴 때의 변경 사항은 릴리스 노트로 확인한다.

### Foundry의 Claude 모델 비용 관리·태깅 (GA)

Foundry에 배포한 Claude 모델 비용이 Azure Cost Management에 Foundry 리소스 기준으로 나타난다. 공식 안내에 따르면 지금까지는 Claude 요금이 SaaS 항목으로 잡혔다.

FinOps 담당자와 Claude를 Foundry로 쓰는 팀이 대상이다. 태그 기반 비용 배분이 가능해진다는 점이 핵심이다.

도입 전에는 기존 비용 보고서·예산 알림이 "SaaS" 기준으로 만들어져 있다면 필터를 다시 맞춰야 한다. 과거 데이터가 소급되는지는 확인하지 못했다.

## 보안·ID

### Confidential VM 대용량 OS 디스크 암호화 (GA)

Confidential VM으로 마이그레이션할 때 큰 OS 디스크도 암호화된 상태로 옮길 수 있다. 공식 안내는 디스크 크기 때문에 기밀 컴퓨팅 이전이 막히던 문제를 해소한다고 설명한다.

규제 워크로드를 기밀 컴퓨팅으로 옮기려던 팀이 대상이다.

지원하는 디스크 크기 상한과 마이그레이션 절차는 이번 확인에서 얻지 못했으므로 공식 문서에서 직접 확인해야 한다.

## 운영·모니터링

### Container Apps 로깅 대상 Log Analytics → Azure Monitor 전환 안내 (은퇴 예고에 가까운 레거시 전환)

Container Apps의 "Log Analytics" 로깅 대상이 레거시 옵션이 됐다. 기존 환경은 정상 동작하지만 Azure Monitor 대상으로 마이그레이션 계획을 세우라는 안내다. 종료일은 이번 게시물에서 확인하지 못했다.

Learn 문서 기준으로 Azure Monitor 대상은 진단 설정으로 Log Analytics 워크스페이스, 스토리지, 이벤트 허브, 파트너 솔루션에 보낼 수 있다. 환경당 진단 설정은 최대 5개다. 기본 Log Analytics 옵션으로 환경을 만들어 쓰던 모든 팀이 대상이다.

도입 전에는 Azure Monitor 대상을 고르면 포털의 Logs 메뉴(쿼리 편집기)가 비활성화된다는 점을 알아야 한다. 같은 워크스페이스로 보내 쿼리하려면 진단 설정을 추가로 구성한다. 또 Private Link 환경에서는 Log Analytics로 직접 전송이 지원되지 않아 Azure Monitor 경유가 필요하다고 문서에 적혀 있다.

## 은퇴·마감 알림

- Container Apps의 Log Analytics 로깅 대상: 레거시 옵션 전환. 기존 환경은 계속 동작하며 종료일은 확인하지 못했다.
- Azure DNS zone 엔드포인트(스토리지, 프리뷰): 2027년 3월 은퇴 예정(Learn 스토리지 계정 개요 문서 기준).
